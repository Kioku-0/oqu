Почему эта технология?

FastAPI — OpenAPI и проверка данных из кода. SQLite — один файл, запуск одной командой. Чистый JS — без сборки.

Как защищены данные?

Хэш с солью, защита от подбора, SQL с параметрами, права на сервере, CSP, ключ вне кода.

Какие граничные случаи?

Длины на границе, страница за концом, оценки 0 и 6, истёкшие бан и платный срок, повторная покупка.

Вторая платформа?

Сервер не меняется: всё есть в API. Нужен клиент на Flet: flet build windows / apk.

Ответы на четыре контрольных вопроса из задания. Почему эта технология? FastAPI — требование варианта, к тому же сам строит документацию OpenAPI и проверяет входные данные по моделям Pydantic. SQLite — база в одном файле без отдельного сервера, проект запускается одной командой на любом компьютере; ограничение по одновременной записи для учебной нагрузки не важно, а переход на PostgreSQL меняет только db.py. Интерфейс на чистом JavaScript не требует сборки. Как защищены данные? Пароли — только хэш с солью, 600 тысяч итераций; защита от подбора; все SQL-запросы с параметрами; права проверяются на сервере; токены подписаны и ограничены по времени, ключ не в коде; вывод экранирован и защищён CSP; база и ключи не попадают в Git. Какие граничные случаи проверены? Логин из двух символов и пароль из семи, ровно пять неудачных входов, страница за пределами списка, размер страницы 10 000, год 3000, оценки 0 и 6, комментарий 2001 символ, бан и платный срок, которые уже истекли, повторная покупка, запись журнала старше года, инъекция в сортировке. Что нужно для второй платформы? Серверная часть не меняется, потому что все функции уже доступны через REST API. Пишем клиент на Flet: для компьютера flet build windows, для телефона flet build apk. Клиенту нужно хранить адрес сервера и токен, переводы берутся из /api/i18n, а переключатель языка переносится в настройки приложения, как принято на этих платформах.
