Три уровня, логика отдельно

Интерфейс

браузер · web.py (FastAPI)

▼ JSON по HTTP + JWT

Бизнес-логика

service.py · без HTTP

▼ параметризованный SQL

Хранилище

db.py · SQLite

Почему так

service.py ничего не знает о вебе — тесты идут без сервера, а ту же логику можно подключить к настольному и мобильному клиенту.

Почему FastAPI

Требование варианта; OpenAPI-документация и проверка данных — из кода.

Почему SQLite

Один файл, без сервера. Запись — одним процессом: для учёбы хватает, переход на PostgreSQL меняет только db.py.

Оқу · как мы строили

7

Архитектура трёхуровневая, как в примере LabBooking из методички. Верхний уровень — интерфейс: браузер и файл web.py на FastAPI. Он только принимает запросы, проверяет права и превращает ошибки логики в HTTP-коды. Средний уровень — service.py, вся бизнес-логика: права ролей, книги, поиск, полки, баны, журнал. Он вообще не знает про HTTP. Нижний — db.py и SQLite. Почему это важно: логику можно тестировать без запуска сервера — 130 тестов идут меньше секунды. И её же можно подключить к настольной или мобильной версии — это ответ на вопрос про вторую платформу. Почему FastAPI: это требование варианта, и он сам строит документацию OpenAPI и проверяет входные данные по моделям Pydantic. Почему SQLite: база в одном файле, не нужен отдельный сервер, проект запускается на любом ноутбуке одной командой. Ограничение — записывать одновременно может только один процесс. Мы включили режим WAL, чтобы чтение не блокировалось записью. При большой нагрузке переходим на PostgreSQL, и меняется только db.py.
