## 3. Правила оформления

- **PEP 8**: отступ 4 пробела, строки ≤ 79 символов, `snake_case` для функций и переменных, `PascalCase` для классов, `UPPER_CASE` для констант; проверка `ruff check --select E,W,F,N` — 0 замечаний.
- **Docstrings** (PEP 257) у каждого модуля и функции, аннотации типов.
- **Без «магических чисел»**: `MIN_PASSWORD_LEN`, `MAX_COMMENT_LEN`, `MAX_PAGE_SIZE`, `LOG_RETENTION_DAYS`, `MAX_FAILED_ATTEMPTS` и др.
- **Исключения бизнес-логики** — иерархия `ServiceError` (`ValidationError`, `AuthError`, `PermissionDeniedError`, `ConflictError`…); веб-слой превращает их в понятные HTTP-ответы, как `BookingError` в примере LabBooking.

## 4. Git

Репозиторий ведётся с первого дня; коммиты содержательные, сообщения на русском в формате `тип(область): что сделано`:

```
feat(core): пакет приложения и схема базы данных (SQLite)
feat(security): хэширование паролей PBKDF2 и JWT-токены
feat(service): бизнес-логика — роли, книги, комментарии, журнал
test: автотесты бизнес-логики (47 тестов, граничные и ошибочные случаи)
…
feat(censor): фильтр мата ru/kk/en с приставками и латинскими двойниками
feat(ui): новый интерфейс «Оқу» — каталог, шкаф с анимациями, читалка…
docs(legal): пользовательское соглашение и политика конфиденциальности
```

Всего более 29 коммитов (требование методички — не менее 10). Посмотреть историю: `git log --oneline`. В репозиторий не попадают база, ключи, загрузки, журналы и виртуальное окружение (`.gitignore`), а также материалы преподавателя.

## 5. Зависимости (`requirements.txt`)

| Пакет | Зачем |
|---|---|
| fastapi | REST API и документация OpenAPI |
| uvicorn | ASGI-сервер для запуска |
| PyJWT | токены JWT |
| pydantic | проверка данных (входит в FastAPI) |
| python-multipart | загрузка файлов (PDF, фото) |
| pytest, ruff | тесты и проверка стиля (для разработки) |
| python-docx | сборка документов в Word (только для `docs/tools`) |

Хэширование паролей, работа с SQLite, сжатие и журналы — стандартная библиотека Python.
