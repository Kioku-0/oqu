## 0. Бесплатно: компьютер разработчика + туннель Cloudflare

Проект учебный и нужен на время защиты, поэтому платный сервер не обязателен. Сайт запускается на ноутбуке, а программа `cloudflared` (бесплатный Quick Tunnel от Cloudflare, без регистрации) выдаёт ему публичную ссылку `https://<случайные-слова>.trycloudflare.com` с HTTPS.

**Как работает.** `cloudflared` сам устанавливает исходящее соединение с Cloudflare, поэтому не нужны ни белый IP, ни открытые порты на роутере. Посетитель → HTTPS → Cloudflare → туннель → `127.0.0.1:8000` на ноутбуке.

**Подготовка (один раз).** Скачать `cloudflared-windows-amd64.exe` с <https://github.com/cloudflare/cloudflared/releases/latest>, переименовать в `cloudflared.exe` и положить в папку `tools\` проекта (папка в `.gitignore`, файл ~53 МБ). Подлинность можно проверить: «Свойства → Цифровые подписи» — Cloudflare, Inc.

**Запуск.** Двойной щелчок по `start_public.bat` (логика — в `run_public.py`):

1. ставит зависимости и готовит базу (как `start.bat`);
2. предлагает задать **свой пароль служебным демо-аккаунтам** (`muhan`, `khadizat`, `moder01`, `author01`, `author02`) — пароль `ChangeMe_2026` опубликован в README, а сайт открыт всем; Enter — оставить прежний;
3. запускает сервер в **публичном режиме** (`OQU_PUBLIC=1`): на странице входа скрыта подсказка с демо-аккаунтами и паролем;
4. включает доверие к заголовку `CF-Connecting-IP` (`OQU_TRUST_PROXY=1`) — иначе все посетители выглядели бы как `127.0.0.1`, делили бы один лимит попыток входа и в журнал попадал бы один адрес. Заголовку верим только от локального туннеля;
5. запускает туннель, крупно показывает ссылку, копирует её в буфер обмена и сохраняет в `instance/public_url.txt`; вывод туннеля — в `instance/logs/tunnel.log`.

**Ограничения.** Сайт доступен, пока ноутбук включён и окно открыто; при каждом запуске ссылка новая; у бесплатного туннеля нет гарантии доступности. Данные (база, загруженные книги) остаются на ноутбуке — на территории РК, как и обещает Политика конфиденциальности.

**Проверено 21.11.2026:** ссылка открывается извне, `/api/health` отвечает `200`, подсказка с паролем скрыта, в журнале — внешний IP посетителя.

## 1. Требования к хостингу

- VPS с root-доступом по SSH, 1 vCPU, 1 ГБ RAM, 10 ГБ диска — достаточно для учебной нагрузки.
- **Сервер в Казахстане** — Закон РК «О персональных данных и их защите» требует хранить базу с персональными данными граждан РК на территории РК.
- Доменное имя (для HTTPS-сертификата Let's Encrypt).

## 2. Подготовка сервера

```bash
sudo apt update && sudo apt install -y python3 python3-venv nginx git
sudo adduser --system --group --home /srv/oqu oqu
sudo -u oqu git clone <адрес репозитория> /srv/oqu/app
cd /srv/oqu/app
sudo -u oqu python3 -m venv /srv/oqu/venv
sudo -u oqu /srv/oqu/venv/bin/pip install -r requirements.txt
```

## 3. Настройки и данные

Секретный ключ — длинная случайная строка в переменной окружения (не в коде):

```bash
sudo mkdir -p /srv/oqu/instance && sudo chown oqu:oqu /srv/oqu/instance
python3 -c "import secrets; print('SECRET_KEY=' + secrets.token_urlsafe(48))" | sudo tee /srv/oqu/oqu.env
echo "OQU_INSTANCE=/srv/oqu/instance" | sudo tee -a /srv/oqu/oqu.env
sudo chmod 600 /srv/oqu/oqu.env
```

Пустая рабочая база создаётся при первом запуске. Главный разработчик создаётся отдельной командой; пароль передаётся через переменную окружения, чтобы не остаться в истории команд:

```bash
cd /srv/oqu/app
sudo -u oqu env OQU_INSTANCE=/srv/oqu/instance OQU_OWNER_USERNAME=muhan OQU_OWNER_EMAIL=<почта> OQU_OWNER_PASSWORD="$(read -rsp 'Пароль: ' p; echo $p)" /srv/oqu/venv/bin/python -m app.seed --create-owner
```

Демо-данные (`python -m app.seed`) на рабочем сервере не загружайте: у демо-аккаунтов общеизвестный пароль.

## 4. Служба systemd (автозапуск)

Файл `/etc/systemd/system/oqu.service`:

```ini
[Unit]
Description=Oqu digital library
After=network.target

[Service]
User=oqu
WorkingDirectory=/srv/oqu/app
EnvironmentFile=/srv/oqu/oqu.env
ExecStart=/srv/oqu/venv/bin/uvicorn app.web:app --host 127.0.0.1 --port 8000 --workers 1 --proxy-headers
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now oqu
```

Один процесс (`--workers 1`) выбран из-за SQLite (запись — одним процессом) и хранения лимита попыток входа в памяти процесса.

## 5. nginx и HTTPS

Файл `/etc/nginx/sites-available/oqu`:

```nginx
server {
    server_name oqu.example.kz;
    client_max_body_size 45m;          # PDF до 40 МБ
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/oqu /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d oqu.example.kz
```

Certbot настроит HTTPS и автоматическое продление сертификата. Брандмауэр: открыть только 22, 80, 443 (`sudo ufw allow OpenSSH && sudo ufw allow 'Nginx Full' && sudo ufw enable`).

## 6. Журналы

- Значимые действия пользователей — в базе, раздел «Модерация → Журнал действий» (выгрузка CSV).
- Все запросы с временем ответа и ошибки — файл `/srv/oqu/instance/logs/oqu.log` (ротация: 5 файлов по 2 МБ).
- Логи службы: `journalctl -u oqu -f`.

## 7. Резервное копирование

Всё изменяемое — в папке `instance/`. Ежедневная копия базы без остановки сервера (cron пользователя `oqu`):

```bash
0 3 * * * sqlite3 /srv/oqu/instance/library.sqlite ".backup '/srv/oqu/backup/library-$(date +\%F).sqlite'" && tar czf /srv/oqu/backup/uploads-$(date +\%F).tgz -C /srv/oqu/instance uploads
```

Хранить копии 14 дней и периодически переносить на другой носитель. Восстановление: остановить службу, заменить файл базы и папку `uploads`, запустить службу.

## 8. Обновление версии

```bash
cd /srv/oqu/app && sudo -u oqu git pull
sudo -u oqu /srv/oqu/venv/bin/pip install -r requirements.txt
sudo systemctl restart oqu
```

Новые столбцы базы добавляются автоматически при запуске (миграции `db.py`); браузеры получат новые файлы интерфейса благодаря версии в адресе (`?v=…`).

## 9. Проверка после развёртывания

- `curl https://oqu.example.kz/api/health` → `{"status":"ok",...}`;
- в ответе есть заголовки `Content-Security-Policy`, `X-Frame-Options`, `Strict-Transport-Security` (добавляется в nginx: `add_header Strict-Transport-Security "max-age=31536000" always;`);
- вход, чтение книги и журнал работают; в `oqu.log` нет ошибок.
