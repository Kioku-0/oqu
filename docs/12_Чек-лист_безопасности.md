# Документ 12. Чек-лист безопасности

**Проект:** «Оқу» · **Версия:** 2.0 от 21.11.2026 · *Дополнительный документ для веб-приложения*

Чек-лист составлен по разделу 5.4 методички и рекомендациям OWASP (Top 10, Authentication / Password Storage / File Upload Cheat Sheets). «✅» - выполнено и проверено; в столбце «Как проверить» указан тест или ручная проверка.

## 1. Хранение данных и SQL

| S-03 | Ограничения целостности в самой БД: внешние ключи, `CHECK` (роль, язык, год, оценка 1-5, статусы) | ✅ | `app/db.py` | Попытка вставить роль `hacker` вручную в SQLite отклоняется |

## 8. Известные ограничения

- Хранилище токенов - `localStorage` браузера. При XSS токен можно украсть; риск снижен экранированием и CSP. Для повышенной защиты можно перейти на cookie `HttpOnly; Secure; SameSite=Strict` (тогда потребуется CSRF-токен).
- Лимит попыток входа по IP хранится в памяти процесса: при нескольких процессах сервера он считается для каждого отдельно (для учебной нагрузки достаточно).
- Выход из аккаунта удаляет токены в браузере, но выданный токен доступа остаётся действительным до истечения 30 минут (особенность JWT без «чёрного списка»).
